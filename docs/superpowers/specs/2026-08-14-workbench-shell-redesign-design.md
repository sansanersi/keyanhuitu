# 科研绘图工作台浅色工作台壳层改版设计

## 1. 目标与范围

本次改版目标是将现有“科研绘图工作台”从深色科技风调整为接近参考图的浅色专业工作台风格，并优先完成以下三部分：

1. 左侧导航
2. 顶部栏
3. 应用平台主框架

本次不重构后端接口，不更换现有数据流，不重写文本库、图片库、设置页的业务逻辑。其余页面只跟随新的壳层样式获得一致的视觉语言，不在本轮大改内部信息架构。

## 2. 设计原则

### 2.1 视觉方向

- 从深色渐变背景切换为浅色、留白更多的工作台界面
- 主色采用低饱和绿色作为强调色，用于选中态、主按钮、关键焦点边框
- 面板以白底和浅灰描边为主，弱化厚重阴影，保留轻量层级
- 整体气质偏“创作工具 / 生产力平台”，避免营销页或大屏化表达

### 2.2 工程原则

- 复用现有模板、页面切换机制和接口调用逻辑
- 优先通过 HTML 结构调整和 CSS 分层完成改版
- JavaScript 仅做最小必要改动，保证现有按钮、状态文案、结果渲染继续可用
- 修改集中在 `sci-illust-system/web_app/templates/index.html`，测试补到前端产物级别

## 3. 页面壳层设计

## 3.1 左侧导航

左侧导航从当前深色悬浮岛调整为浅色工具栏式导航，布局上仍然保留固定左侧入口，避免影响现有分页认知。

设计特征：

- 白色或近白底面板
- 细描边、轻阴影、较小圆角
- 顶部包含产品标识和当前模块提示
- 导航项采用“工具入口”风格，选中态使用浅绿色底和绿色描边
- 非选中态强调简洁、可扫视，不使用厚重渐变

交互要求：

- 保留现有 `data-page` 驱动的页面切换
- 选中态、hover、focus 可明显区分
- 移动端保持横向导航收纳策略，但样式同步为浅色胶囊按钮

## 3.2 顶部栏

顶部栏由当前偏内容标题区的样式调整为浅色操作栏，作用是承接产品名、当前页面名称、环境状态和保留操作位。

设计特征：

- 横向白底顶栏，与主内容区有清晰分隔
- 左侧为产品名和当前模块信息
- 右侧为状态信息、轻量操作位或占位操作按钮
- 高度控制在紧凑工作台尺度，避免过高首屏占用

兼容策略：

- 保留现有状态胶囊数据来源
- 顶栏结构允许后续扩展诸如模型状态、配额、快捷入口，但本轮先不接新接口

## 4. 应用平台主框架设计

应用平台页是本轮的重点高仿区域，整体结构改为“左侧参数面板 + 右侧主预览工作区”。

## 4.1 左侧参数面板

目标是接近参考图中的配置栏体验，但保留当前系统已有能力。

面板区块规划：

1. 生成模式
   - 以分段按钮或宫格按钮展示，例如“文字图 / 草图转图像 / 编辑图片”
   - 本轮若后端暂未真正支持全部模式，可保留视觉入口，其中当前可用模式明确高亮
2. 图片描述
   - 使用更大的白底输入框
   - 显示字数计数或长度提示
3. 图片语言 / 输出语言
   - 对应当前系统的领域或生成语言相关配置位，若无完整后端含义，则以前端配置位形式呈现
4. 图片分辨率
   - 映射当前画布尺寸选择
5. 图片生成数量
   - 以前端选择器形式展示，若当前接口暂不支持多图并发，则保留 UI 并在提交时按当前后端能力退化
6. 高级选项
   - 收纳布局、风格、模型等已有参数
7. 主操作按钮
   - 显著绿色主按钮，承接“生成图片”

### 4.2 右侧主工作区

右侧主工作区负责承接空状态、生成预览、流程说明和结果分析。

结构分层：

1. 空状态欢迎卡
   - 在未生成内容时展示中心化欢迎区
   - 包含标题、说明、能力卖点和提示信息
2. 预览区
   - 当生成 SVG 或流程后替换空状态的主视觉区域
   - 保留下载 SVG、结果摘要、来源标识
3. 能力说明 / 提示区
   - 将当前页面已有“识别元素、关系、AI 绘图流程”等内容改造成更有层次的工作台说明区
4. 流程与结果区
   - 保留现有流程结果渲染能力，但使用浅色卡片风格重排

### 4.3 视觉细节

- 背景以极浅灰白为主
- 卡片使用 8px 到 16px 范围内圆角，避免过度圆润
- 输入框、分段选择器、数量按钮均采用浅绿色选中反馈
- 主按钮固定在面板底部附近，但不使用真正 `fixed`，避免移动端遮挡

## 5. 结构与代码调整方案

## 5.1 模板层

主要调整 `index.html` 中以下部分：

- `.app` 总体布局
- `.sidebar` 左侧导航结构和样式
- `.topbar` 顶部栏结构和样式
- `drawingApp` 页签下的 DOM 结构
- 与应用平台有关的空状态、预览头、分析区、流程区布局

必要时为应用平台新增更语义化的类名，例如：

- `workbench-shell`
- `workbench-topbar`
- `creator-sidebar`
- `creator-canvas`
- `creator-empty-state`
- `creator-option-group`

## 5.2 样式层

会将现有大量深色变量扩展或替换为浅色工作台变量，例如：

- 背景色变量
- 边框色变量
- 文本层级变量
- 绿色强调色变量
- 浅色卡片阴影变量

策略上以“增量替换”为主，不一次性清空所有旧变量，避免影响非目标页面。

## 5.3 交互层

JavaScript 保持以下行为不变：

- 分页切换 `switchPage`
- 生成流程 `generateWorkflow`
- 生成配图 `generateDrawing`
- SVG 下载
- 模型配置与状态读取

可能需要补充的轻量交互：

- 模式按钮切换的选中态
- 高级选项的折叠/展开
- 空状态与预览状态的显隐切换样式

这些交互原则上在现有脚本内小范围补充，不拆分为新模块。

## 6. 风险与兼容性

### 6.1 风险

- 现有 `index.html` 是单文件聚合模板，CSS 和结构耦合度较高，改版时容易影响其他页签
- 应用平台当前已有结果区、流程区、分析区，重排时若类名覆盖不稳，可能导致局部错位
- 参考图是更偏创作工具的产品 UI，而当前系统是多页工作台，不能完全复制其信息架构

### 6.2 控制方式

- 优先局部新增类名，不在全局直接粗暴替换通用类
- 针对壳层和应用平台新增前端产物测试，避免导航、页面切换、关键按钮文案被误删
- 保持接口、按钮 ID、关键容器 ID 不变，确保 JS 绑定不断裂

## 7. 测试与验收

本轮验收分为三层：

### 7.1 静态产物测试

更新或新增测试，检查：

- 左侧导航仍包含核心页签
- 顶部栏保留产品信息和状态区域
- 应用平台具备新的工作台结构类名
- 关键按钮和关键容器仍存在

### 7.2 行为回归测试

至少验证：

- 页面切换正常
- 生成配图按钮仍可触发原逻辑
- 生成流程按钮仍可触发原逻辑
- 下载 SVG 按钮仍保留

### 7.3 部署验收

若本轮进入上线：

- 同步 `index.html`
- 重启 `keyanhuitu` 服务
- 验证服务器本机入口和公网入口返回 200
- 人工确认应用平台页结构、左侧导航、顶部栏已切换为新样式

## 8. 非目标项

本轮明确不做：

- 后端接口重构
- 文本库、图片库、设置页的信息架构重做
- 全站设计系统完全组件化
- 多路由拆分或前端框架迁移
- 新增真实图片编辑、草图转图等完整后端能力

## 9. 实施建议

建议实施顺序：

1. 先改左侧导航和顶部栏的壳层样式
2. 再重构应用平台 DOM 结构与浅色工作台样式
3. 最后做交互态补齐与回归测试

这样可以先稳定全局外壳，再集中处理参考图最关键的应用平台区域，减少一次性大改导致的回归风险。
